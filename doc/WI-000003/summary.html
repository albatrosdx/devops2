2. 要件

  1. 見積（Quote__c）・見積明細（QuoteLineItem__c）をカスタムオブジェクトとして新規作成する（標準Quoteは使わない）
  2. 一般的な見積書に記載される項目を両オブジェクトに追加する
  3. 見積書をPDF出力するLWCを作成する。LWC単体で完結させる（Visualforce不使用）
  4. そのLWCを見積オブジェクトのアクションとして登録する
  5. 消費税は明細ごとの税率を持たせ、税率別に集計する（軽減税率・インボイス制度対応）

3. 設計上の主な判断

PDF生成方式 — 実測で決定

「LWCで実現できないか調査して」というご要望を受け、着手前に実機で検証しました。

フォント構成 TTF base64 静的リソース5MB上限
Noto Sans JP 全CJK（約2万字） 4.17 MB 5.57 MB 超過
JIS X 0208（第一・第二水準）7,423字 2.19 MB 2.92 MB 収まる
  • jsPDF は v3以降がLocker環境で動作しないため 2.5.1 に固定
  • 日本語フォントは JIS X 0208 へサブセット化。文字集合は Python の cp932 コーデックから機械的に導出しており、外部の文字リストに依存せず再現可能
  • 生成手順は scripts/font/build-japanese-font.py に保存済み。ライセンスは SIL OFL 1.1 で再配布可
  • 約2.9MBのフォントはボタン押下時に遅延ロード（モーダル表示は即座）
  • html2canvas方式は文字選択・検索ができず、window.print() はPDFを組織内に保存できないため不採用

消費税の端数処理

インボイス制度は「税率ごとに1回の端数処理」を求めるため、明細ごとに切り捨てるのではなく、税率別の課税対象額を積み上げ集計してから切り捨てる構成にしました。明細の TaxAmount__c は表示用で、合計計算には使いません。 

TaxableBase10__c = SUM(明細.Amount__c) WHERE TaxRate__c = '10%'   ← 積み上げ集計
TaxAmount10__c   = FLOOR(TaxableBase10__c * 0.1)                  ← 数式
TotalAmount__c   = Subtotal__c + TaxAmount10__c + TaxAmount8__c

Apexテストには、単価1,105と2,105の10%明細2行（明細ごと切り捨てなら320円、税率ごとなら321円）でこの差を検証するテストを含めています。

その他

  • 自社情報はハードコードせず、カスタムメタデータ型 QuoteIssuer__mdt に分離
  • Apexは with sharing + WITH USER_MODE。権限不足時の内部エラーは利用者向け文言に置換

7. 途中で発生した問題と対処

本番検証でApexテストが10件全滅

Scratch組織では全件パスしていたのに、本番 check-only 検証で以下により全滅しました。 

System.DmlException: Operation failed due to fields being inaccessible on Sobject Quote__c

当初の見立ては誤りでした。「Scratch組織ではFLSが自動付与される」と判断しましたが、実測により否定されました。真因は次の2つです。

  1. メタデータAPI経由で作成したカスタム項目には、どのプロファイルにもFLSが付与されない
  2. テストクラスが実行ユーザーの既存権限に暗黙依存していた。Scratch組織では開発中に管理者へ QuoteManagement を手動割り当てしていたため通っていただけで、組織差ではなくテストの設計上の欠陥

対処: 本番から Admin プロファイルを取得して権限を追加し、テストは QuoteManagement を割り当てた専用ユーザーを作って System.runAs 内で実行するよう修正。再検証で本番 55/55・テスト10/10パス。

QuickActionのスキーマエラー4連続

LWC開発者ガイドの記載どおりに書いたところ、デプロイが4回連続で失敗しました。ガイドの要素名・列挙値が実際のメタデータスキーマと一致していなかったためです。

誤り 正しい形
<apiVersion> 無効な要素。省略する
<targetSobjectType> <targetObject>。オブジェクト固有ならファイル名でスコープが決まるため省略可
<type>ScreenAction</type> <type>LightningWebComponent</type>（ScreenAction はLWC側 js-meta.xml の <actionType> の値）
<optionsCreateFeedItem> の省略 必須要素

8. 未達の項目

クイックアクションのレコードページ配置（保留）

QuickAction 自体は作成・本番デプロイ済みですが、LWCクイックアクションはページレイアウトの <quickActionList> に追加できません。 

QuickActionType LightningWebComponent を QuickActionList に追加できません。

レコードページに表示するには FlexiPageの動的アクションが必要です。利用者のご判断により本作業では保留としました。

管理者による設定手順（数分）:

  1. 見積レコードを開き、[設定] → [編集ページ]
  2. ハイライトパネルを選択し、[アクション] を「動的アクションをアップグレード」
  3. [アクションを追加] から「見積書PDF出力」を選択
  4. [保存] → [有効化] → 組織のデフォルトに設定

その後の検討をおすすめする点

セキュリティ指摘ではなく設計論点として、Quote__c のOWDが Public Read/Write（カスタムオブジェクトの既定値）かつ権限セットで allowDelete=true のため、権限セット保有者は任意の見積を削除でき、主従関係により明細も連鎖削除されます。見積は顧客名・金額・支払条件を含む文書のため、OWDを非公開にして共有ルールで開放する設計が妥当かどうか、業務側とのご確認をおすすめします。本作業ではOWD変更をスコープ外としています。
